# AI实战X Traction Operating System — v1.0

**Status:** ACTIVE  
**Effective:** 2026-09-24  
**Authority:** subordinate to `PROJECT_SPEC.md`; where this file adds operating detail without conflict, it is mandatory.

## 1. Purpose

Apply the operating ideas from *Traction* to AI实战X as an experiment system, not as a posting checklist.

The question is not “how much content did we produce?” It is:

> Which repeatable acquisition loop brings the right AI/Agent/productivity audience to Kenny, gives them a clear reason to follow, and can be scaled without lowering content quality?

## 2. Traction Goal

The current Traction Goal is to prove a repeatable loop from:

```text
first-hand evidence / differentiated thesis
  -> right distribution surface
  -> profile interest
  -> relevant follow
  -> repeated interaction / creator relationship
```

Follower milestones in `config/kpi.toml` are directional checkpoints, not quotas. A milestone miss triggers diagnosis and a new experiment; it never authorizes generic volume.

## 3. Critical Path

Until evidence says otherwise, the current Critical Path is:

1. produce recognizable first-hand evidence from Kenny's real AI work;
2. turn it into one strong owned thesis/content asset;
3. distribute through the best-fit X conversations and creators;
4. capture outcome evidence;
5. identify which topic / creator / format converts to relevant follows;
6. repeat the winning pattern before broadening.

Work that does not remove the current bottleneck is secondary.

## 4. Bullseye

Use three rings.

### Outer Ring — hypotheses worth testing

Examples:
- first-hand benchmark / build evidence;
- contrarian operating lesson;
- creator Reply / Quote distribution;
- public tools, checkers, scorecards and datasets;
- community participation;
- long-form Article / Thread;
- Spaces / podcasts / guest appearances;
- newsletter or owned distribution later.

Do not fund or operationalize all of them.

### Middle Ring — small tests

Keep roughly three serious growth hypotheses active at a time when evidence permits. Each test needs:
- channel / tactic;
- audience;
- hypothesis;
- cheapest valid test;
- success evidence;
- time / cost budget;
- decision date.

Tests should be cheap enough to kill quickly.

### Bullseye — concentration

When one loop materially outperforms the others on relevant follower conversion, profile interest, mature engagement or durable relationship evidence:
- concentrate content and operator attention there;
- repeat it enough to test repeatability;
- stop weak parallel activity;
- only reopen the outer ring when the winner saturates or stops moving the needle.

## 5. Current channel thesis

### Core
- X as the existing platform;
- owned Content Marketing based on Kenny's real AI work;
- targeted Creator / Reply distribution around overlapping technical audiences.

### High-priority adjacent bet
- Engineering as Marketing: useful public assets made from work we already do.

Examples:
- model selector / local-LLM fit checker;
- Agent runtime benchmark;
- Research Factory benchmark;
- cost / latency / reliability calculators;
- public scorecards, checklists or reproducible datasets.

A useful tool that compounds discovery for months is strategically more valuable than a disposable filler post.

### Later / evidence-gated
- Community Building;
- Spaces, podcasts, guest content;
- newsletter;
- publicity;
- paid acquisition.

No channel is promoted because a book recommends it; it earns resources through evidence.

## 6. Content as acquisition experiments

Every meaningful owned Post / Thread / Article should answer:
- What is the hypothesis?
- What unique evidence or thesis does Kenny own?
- Which audience is this trying to acquire?
- What outcome would count as evidence?
- Is this reusable as a durable content or engineering asset?

Priority:
```text
real project evidence
> experiment / benchmark / failure + recovery
> distinctive thesis
> consequential verified change
> ordinary news commentary
```

The last category is normally SKIP.

## 7. Reply as creator acquisition

Reply is not a content quota. It is a high-touch early-stage acquisition tactic.

Prefer opportunities where:
- creator audience overlaps the target audience;
- the parent conversation has real distribution;
- Kenny can add first-hand evidence, a key number, correction, comparison or useful judgment;
- a relationship or repeat interaction is plausible.

Measure:
- mature Reply impressions;
- creator response / repeat interaction;
- profile-interest evidence where available;
- relevant follower evidence where available;
- whether the Reply creates a thesis worth owning later.

Do not increase Reply volume merely because the daily count is low.

## 8. Engineering as Marketing rule

Whenever a real project generates a reusable internal tool, benchmark, evaluator, dataset, checklist or visualization, ask:

> Can this become a useful public asset that solves a small problem for the target audience?

If yes, add it to the growth-experiment backlog. Do not build marketing toys detached from real user value.

## 9. Experiment discipline

One growth experiment record should contain:

```text
Hypothesis:
Audience:
Channel/tactic:
Asset/content:
Primary measure:
Secondary evidence:
Budget:
Start:
Decision date:
Result:
Decision: SCALE | ITERATE | KILL | INCONCLUSIVE
Learning:
```

Prefer changing one major growth variable at a time. Instrumentation fixes may happen in parallel.

## 10. Review rule — move the needle

Daily review:
- identify the first broken funnel stage;
- name the current Critical Path bottleneck;
- recommend one next growth variable, not a pile of activity.

Weekly / sufficient-sample review:
- compare active Bullseye tests;
- promote a winner only with outcome evidence;
- kill or downgrade tests that consume attention without moving the needle;
- reopen exploration when the current Bullseye stalls or saturates.

## 11. Guardrails

- no automatic X publishing;
- no guaranteed growth claims;
- no fabricated attribution from a follower delta to a single post/creator;
- impressions are distribution evidence, not Traction by themselves;
- follower milestones do not justify lowering the editorial gate;
- do not optimize for posting volume;
- do not let infrastructure work become the product unless it removes the current acquisition bottleneck.
